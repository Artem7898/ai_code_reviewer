## Что именно покрыто

- Argon2id, проверка старого bcrypt, отсутствие seed-аккаунта, строгие JWT claims и отзыв токенов при смене пароля.
- Параллельный сброс пароля и compare-and-swap при обновлении bcrypt: старый пароль не восстанавливается поверх нового.
- Анонимный и межпользовательский доступ, Django staff/view permissions, безопасное отображение отчётов.
- Traversal, symlink/hardlink, специальные файлы, смена ссылки во время чтения, перезапись через имя загрузки.
- Параллельные загрузки одного имени без коллизий и оставленных временных файлов.
- Снимки очереди неизменны; хэши патчей проверяются и при создании артефакта, и перед изолированным запуском. Изменение вне hunk не принимается незаметно.
- Атомарные quota/dedup/claim, lease fencing, восстановление после перезапуска, отмена, timeout и отсутствие оставшихся worker-задач.
- Дневной UTC-бюджет: параллельные процессы, перезапуск, смена суток и консервативное округление сумм.
- Ограниченные тела HTTP, chunked-запросы, общий deadline, медленная передача частями, освобождение слотов и ограниченный кэш лимитера.
- Списки заданий не загружают большие payload/result; полный результат читается отдельно. Интерфейс не загружает его повторно на каждом poll.
- Ошибки провайдера, JSON/схема, неверные пути/строки/цитаты, retry и закрытие HTTP-клиента проверены без реального внешнего вызова.
- Git clean filters не выполняются: анализ использует сырые объекты Git, bounded reads и сравнение хэшей.
- PDF разбирается отдельным процессом с лимитами; сгенерированный Python выполняется исключительно в ограниченном контейнере.

Реальный Docker-тест подтвердил UID 65534, отсутствие исходного `.env` и host environment, read-only `/code`, отсутствие исходящей сети, применение предложения только в копии и удаление контейнера после бесконечного теста. Он не доказывает содержательную правильность произвольных сгенерированных тестов.

Compose-проверка прошла путь **HTTP → SQLite job → отдельный worker → findings → SARIF → общая история Django** в static-режиме. Проверены авторизация, локальные CSS/JS, готовность БД, read-only mount проекта и непривилегированный пользователь. Тестовые контейнеры, сеть и том удалены.

## Производительность и ограничения доказательств

`python -m app.evaluate` проверил восемь небольших размеченных AST-примеров: TP 4, FP 0, FN 0, TN 4. Один запуск занял около 3.6 ms, пик `tracemalloc` — 32 629 байт. Это проверка регрессий ограниченного набора правил; показатели не описывают качество LLM, RSS всего сервера или ускорение относительно старой версии.

Рост памяти ограничен размером контекста/ответов, числом worker, HTTP-пулами, четырьмя ingress-слотами по умолчанию и ограниченной загрузкой списков. Длительный production soak-тест не выполнялся; универсальное отсутствие утечек не заявляется. История растёт на диске до явной команды retention; отчёты сохраняются по умолчанию.

Реальные Mistral/Ollama-запросы и качество выбранной модели **не проверены**: облачный ключ не предоставлен, веса локальной модели не загружались. Static-проверки и mock-клиенты не заменяют эту проверку. Для реального AI настройте локальный endpoint/model либо безопасно предоставьте Mistral key, разрешите облачную отправку и задайте цены/бюджет. Проверка потенциальных секретов эвристическая и не заменяет политику обработки данных.

Команды GitHub Actions выполнены локально. Состояние удалённых запусков следует проверять отдельно в [GitHub Actions](https://github.com/Artem7898/ai_code_reviewer/actions); эта таблица описывает локальную валидацию. Публикация облачной среды и восстановление в новой задаче не проверялись.
