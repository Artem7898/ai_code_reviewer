# AI Code Reviewer — Python 3.14

[English](README.md) · **Русский**

Локальный помощник для ревью Python-кода: Git diff → AST/Ruff → необязательная языковая модель → структурированные замечания и SARIF. FastAPI предоставляет API и интерфейс, отдельный worker выполняет длительные задания, Django показывает историю.

По умолчанию используется локальный Ollama. Для детерминированных проверок без модели задайте `AI_PROVIDER=static`. Облачный Mistral включается явно. Проекты доступны только для чтения: предложения миграции и тестов сохраняются отдельно, исходники автоматически не заменяются.

[Архитектура и миграция](docs/ru/MODERNIZATION.md) · [Результаты проверок](docs/ru/VALIDATION.md) · [Защита ветки](docs/ru/BRANCH_PROTECTION.md)

## Установка

Требуются Linux, Python **3.14.8**, Git и [uv](https://docs.astral.sh/uv/). Версии зависимостей и их хеши зафиксированы в `uv.lock`. Рабочий каталог всех следующих команд — корень репозитория.

```bash
uv sync --frozen
cp .env.example .env
mkdir -p projects
uv run --frozen python -m app.cli init-db
uv run --frozen python -m app.cli create-user reviewer --admin
uv run --frozen python admin_panel/manage.py migrate --noinput
uv run --frozen python admin_panel/manage.py createsuperuser
uv run --frozen python admin_panel/manage.py collectstatic --noinput
```

Команды создания пользователей запрашивают пароль; готовых учётных записей нет. API и Django используют отдельные учётные записи. Для автоматизации API поддерживает `--password-env VARIABLE`: пароль читается из уже настроенной переменной окружения и не передаётся аргументом командной строки.

При обновлении существующей установки сначала сделайте резервную копию базы; порядок описан в [руководстве по модернизации](docs/ru/MODERNIZATION.md). Старый автоматически созданный API-пользователь `admin` отключается при миграции. Его можно явно восстановить с новым паролем:

```bash
uv run --frozen python -m app.cli create-user admin --admin --reset-password
```

В разработке приложение создаёт случайный ключ подписи в `.data/signing.key` с правами `0600`. Не удаляйте этот файл между запусками. В production обязателен собственный случайный `SECRET_KEY` длиной не менее 32 символов; пример генерации есть в `.env.example`. Значение хранится в настройках окружения или локальном `.env`.

## Запуск

В трёх терминалах:

```bash
uv run --frozen uvicorn app.main:app --host 127.0.0.1 --port 8000 --limit-concurrency 32
uv run --frozen python -m app.cli worker
uv run --frozen uvicorn admin_panel.asgi:application --app-dir admin_panel --host 127.0.0.1 --port 8080
```

Интерфейс API доступен на порту 8000, Django — на 8080. `/healthz` проверяет процесс API; `/readyz` проверяет доступность базы. Эти проверки не подтверждают наличие модели. `/stats/` требует входа в Django. Публичное развёртывание требует HTTPS на обратном прокси и настройки разрешённых хостов.

Поместите репозиторий отдельным каталогом внутрь `PROJECTS_ROOT`, например `projects/my_project`. Символьные и жёсткие ссылки, абсолютные пути, выход через `..`, `.env` и служебные каталоги исключены. Приложение рассчитано на Linux; безопасная работа с файловыми дескрипторами использует `openat`/`O_NOFOLLOW` и `/proc`.

### Локальная модель

Установите [Ollama](https://ollama.com/), запустите его и скачайте модель:

```bash
ollama pull qwen2.5-coder:7b
```

Используются OpenAI-совместимый endpoint `http://127.0.0.1:11434/v1` и модель из `OLLAMA_MODEL`. Выберите модель под доступную память. Режим `static` выполняет AST/Ruff без сетевого обращения; генерации кода в этом режиме нет.

### Mistral

В защищённых настройках окружения задайте `AI_PROVIDER=mistral`, `ALLOW_CLOUD_AI=true`, `MISTRAL_API_KEY`, положительный `AI_MAX_COST_USD` и актуальные `AI_INPUT_COST_PER_MILLION`/`AI_OUTPUT_COST_PER_MILLION`. Без этих настроек облачная обработка отклоняется. Код выбранных файлов передаётся провайдеру. HTTPX учитывает стандартные переменные HTTPS-прокси для облачного endpoint и проверяет TLS.

Бюджет заданий ограничивает консервативно зарезервированную стоимость запросов за сутки UTC, включая повторные попытки. Запись в общей БД атомарна между worker и сохраняется после перезапуска. Это оценка по заданным ценам и верхним границам токенов, а не биллинг провайдера; дополнительно настройте финансовый лимит у провайдера. Отдельные установки с разными БД имеют отдельные бюджеты.

## Docker Compose

Создайте `.env` по примеру, заполните `SECRET_KEY`, укажите `PROJECTS_DIRECTORY` и замените `OLLAMA_BASE_URL` на `http://ollama:11434/v1` для встроенного Ollama.

```bash
docker compose --profile local-ai up --build -d
docker compose exec ollama ollama pull qwen2.5-coder:7b
docker compose exec app python -m app.cli create-user reviewer --admin
docker compose exec admin python admin_panel/manage.py createsuperuser
```

Для уже работающего Ollama настройте доступный из контейнеров endpoint и запускайте `docker compose up --build -d` без профиля. `localhost` внутри контейнера относится к этому контейнеру.

Init-сервис подготавливает обе схемы и статические файлы, после чего запускаются API, admin и worker. Они используют одну БД `/data/reviewer.sqlite3` в томе `reviewer-data`. Контейнер приложения работает от непривилегированного пользователя с корневой файловой системой только для чтения; каталог проектов монтируется `ro`. Порты опубликованы только на `127.0.0.1`. `.env` не включается в образ.

Файловые права каталога проектов должны разрешать UID/GID `10001:10001` чтение выбранных файлов и проход по каталогам, включая `.git`. При закрытых правах используйте согласованную группу или точечные ACL. Приложение не меняет права ваших репозиториев автоматически.

Compose по умолчанию использует `development` для локального HTTP-доступа, с `DJANGO_DEBUG=false` и обязательным отдельным ключом. Образ сам по себе использует `production`. Для публичного развёртывания задайте `ENVIRONMENT=production` и настройте HTTPS: Django включает перенаправление на HTTPS и secure cookies. Завершая TLS на прокси, настройте доверие к заголовку схемы только для контролируемого прокси, который удаляет поддельные входящие заголовки; автоматического доверия любому `X-Forwarded-Proto` нет.

`OLLAMA_IMAGE` позволяет закрепить проверенную версию или digest образа. Значение `latest` в примере предназначено для локального запуска; модель и внешний образ не входят в Python lockfile.

Сборка поддерживает стандартные Docker proxy build args (`HTTP_PROXY`, `HTTPS_PROXY` и их варианты в нижнем регистре). Для корпоративного удостоверяющего центра можно передать публичный CA bundle через BuildKit secret `build_ca`, например `docker build -t ai-code-reviewer:local --secret id=build_ca,src=/path/to/ca-bundle.pem .`, затем `docker compose up --no-build -d`. Bundle используется только при установке Python-пакетов; проверка TLS и хешей сохраняется, файл не включается в образ.

## Ревью и предложения изменений

Основной режим ревью — изменения относительно Git ref; полный проход включается явно. Контекст ограничен количеством файлов и байтов: превышение приводит к понятной ошибке, код незаметно не обрезается. Замечание содержит правило, важность, относительный путь, диапазон строк и точную цитату из проверенного снимка. Несуществующие координаты и неподтверждённые цитаты отклоняются.

Длительные операции возвращают задание. Worker выполняет его отдельно от API, сообщает статус и прогресс; задание можно отменить. Ошибки модели, неверный JSON, таймауты и превышение бюджета приводят к ошибке задания и не создают успешный отчёт. Результаты и кэш разделены по владельцам.

После входа через `POST /token` передавайте токен в `Authorization: Bearer …`. `POST /api/scan-local-project` принимает `project_name`, `mode=diff` и `base_ref` как поля формы и возвращает HTTP 202 с `id` задания. Для полного прохода задайте `mode=full`.

| Запрос | Результат |
| --- | --- |
| `GET /api/jobs` | Задания текущего пользователя |
| `GET /api/jobs/{id}` | Статус, прогресс, результат или ошибка |
| `POST /api/jobs/{id}/cancel` | Отмена задания |
| `GET /api/jobs/{id}/sarif` | SARIF завершённого ревью |
| `GET /api/jobs/{id}/artifacts` | Файлы готового предложения |

Миграция кода, генерация тестов и scaffolding создают предложения в `DATA_DIR/artifacts`. Python-код проходит проверку синтаксиса, unified diff строит сервер. Автоматического применения к исходникам нет. Запуск сгенерированных тестов разрешён только при наличии поддерживаемой изоляции; статус `unavailable` означает, что тесты **не выполнялись**. Проверка синтаксиса не доказывает корректность поведения.

### CLI и PR-интеграция

```bash
uv run --frozen python -m app.review_cli ./projects/my_project \
  --base-ref HEAD~1 --provider static --output review.json --sarif review.sarif
```

Статический workflow допускает до 1 000 000 байт исходников за ревью. Локальный и API-лимит по умолчанию — 200 000 байт. При превышении заданного лимита анализ останавливается без частичного отчёта.

Workflow `.github/workflows/review.yml` анализирует diff pull request без модели и публикует JSON/SARIF как артефакты сборки. Он не отправляет исходники внешнему LLM и не выполняет анализируемый код. Загрузка SARIF в GitHub Code Scanning при необходимости настраивается отдельно с соответствующим разрешением `security-events: write`.

## Конфигурация

Переменные нечувствительны к регистру; списки задаются JSON-массивами. Все процессы должны использовать одинаковые `DATABASE_PATH`, `DATA_DIR` и ключ подписи.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ENVIRONMENT` | `development` | `development`, `test` или `production` |
| `DATABASE_PATH` | `database.db` в репозитории | Общая SQLite-БД, лучше абсолютный путь |
| `DATA_DIR` | `.data` в репозитории | Ключ разработки, загрузки и артефакты |
| `PROJECTS_ROOT` | `projects` в репозитории | Каталог разрешённых проектов |
| `AI_PROVIDER` | `ollama` | `ollama`, `mistral`, `static` |
| `ALLOWED_HOSTS` | localhost, 127.0.0.1, testserver | Разрешённые хосты API и Django |
| `CORS_ORIGINS` | `[]` | Явные доверенные origins |
| `MAX_REVIEW_FILES` | `100` | Максимум файлов в снимке |
| `MAX_REVIEW_CHARS` | `200000` | Ограничение контекста |
| `MAX_FILE_BYTES` | `1048576` | Размер одного файла |
| `MAX_UPLOAD_BYTES` | `10485760` | Размер загрузки |
| `MAX_PDF_PAGES` | `50` | Максимум страниц PDF |
| `WORKER_CONCURRENCY` | `2` | Число параллельных заданий на процесс |
| `HTTP_CONCURRENCY` | `4` | Одновременные HTTP-обработчики, включая хеширование паролей |
| `MAX_JOBS_PER_USER` | `10` | Очередь незавершённых заданий пользователя |
| `JOB_TIMEOUT_SECONDS` | `600` | Таймаут обработки задания |
| `CACHE_TTL_SECONDS` | `3600` | Срок повторного использования результата |

Полный перечень и допустимые диапазоны находятся в `app/settings.py`. Значения токенов, паролей и ключей не следует включать в журналы или отчёты. Загруженный код и история сохраняются локально: настройте резервное копирование, доступ к диску и срок хранения под свои требования.

Старые завершённые, ошибочные и отменённые задания можно удалить отдельной командой `uv run --frozen python -m app.cli prune --days 30 --limit 100`. Она обрабатывает одну ограниченную порцию и удаляет снимки/результаты/артефакты этих заданий; историю отчётов сохраняет. Флаг `--include-reports` явно включает удаление связанных отчётов. Активные задания не затрагиваются; автоматической очистки по расписанию нет.

## Проверки

```bash
uv run --frozen ruff check .
uv run --frozen mypy
PYTHONPATH=admin_panel:. uv run --frozen mypy --config-file admin_panel/mypy.ini
uv run --frozen python -m pytest -q
uv run --frozen python admin_panel/manage.py check
uv run --frozen python admin_panel/manage.py test core --noinput
uv run --frozen python -m app.evaluate
uv run --frozen pip-audit --require-hashes --no-deps -r requirements.txt
```

Mypy работает в строгом режиме для `app` и отдельно для Django с django-stubs. Набор тестов проверяет аутентификацию, границы файлового доступа, обработку сбоев провайдера, изоляцию владельцев и конкурирующих worker. Benchmark использует небольшой размеченный набор регрессий AST; его precision/recall характеризуют только этот набор и не измеряют качество LLM.

Проверка настоящей Docker-песочницы запускается отдельно: после загрузки `python:3.14.8-slim` выполните `RUN_DOCKER_TESTS=1 uv run --frozen python -m pytest -q tests/test_sandbox.py`. Она проверяет отключённую сеть, непривилегированного пользователя, отсутствие наследования секретов, исходники только для чтения и завершение по таймауту. Основной CI не требует доступного Docker daemon.

`requirements.txt` — экспорт runtime-зависимостей с хешами для инструментов, которым нужен pip. Обновление зависимостей выполняется осознанно:

```bash
uv lock --upgrade
uv sync --frozen
uv export --frozen --no-dev --no-emit-project --format requirements-txt --output-file requirements.txt
```

После обновления выполните проверки выше. Подробности архитектуры, исправлений и ограничений: [руководство по модернизации](docs/ru/MODERNIZATION.md). Результаты и границы выполненных проверок: [отчёт о валидации](docs/ru/VALIDATION.md).
